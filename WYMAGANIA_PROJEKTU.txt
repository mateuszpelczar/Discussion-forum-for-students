BAZA DANYCH:
------------
PostgreSQL na Aiven (cloud)
6 tabel:
1. Uzytkownik (extends AbstractUser) - auth_user
2. Profil (OneToOne z Uzytkownik) - users_profil
3. Kategoria - forum_kategoria
4. Watek (ForeignKey Uzytkownik, Kategoria) - forum_watek
5. Post (ForeignKey Uzytkownik, Watek) - forum_post
6. Glos (ForeignKey Uzytkownik, Post, unique together) - forum_glos

Relacje:
- Uzytkownik 1:1 Profil
- Uzytkownik 1:N Watek (autor)
- Uzytkownik 1:N Post (autor)
- Uzytkownik 1:N Glos
- Kategoria 1:N Watek
- Watek 1:N Post
- Post 1:N Glos

AUTORYZACJA JWT:
----------------
Flow:
1. Login → POST /api/auth/logowanie/
2. Backend zwraca: {access_token, refresh_token, uzytkownik}
3. Frontend zapisuje tokeny w localStorage
4. Każde API call → Authorization: Bearer <access_token>
5. Token expired → użyj refresh_token dla nowego access_token
6. Logout → usunięcie tokenów z localStorage

Bezpieczeństwo:
- Hasła hashowane (Django pbkdf2_sha256)
- CORS restricted (tylko localhost:5173)
- @permission_classes([IsAuthenticated]) na endpointach
- @permission_classes([JestAdministratorem]) dla admina

ZASADY PROGRAMOWANIA:
---------------------
KISS (Keep It Simple):
- Proste kontrolery z jedną odpowiedzialnością
- Bezpośrednia logika bez nadmiernych abstrakcji
- Czytelne nazwy funkcji

DRY (Don't Repeat Yourself):
- Centralna konfiguracja axios (utils/axios.ts)
- Reużywalne serializery i serwisy
- AuthContext zamiast duplikacji logiki
- Wspólny komponent Navbar

YAGNI (You Aren't Gonna Need It):
- Implementacja tylko wymaganych funkcji
- Brak nadmiarowych features

SOLID:
- S: Osobne kontrolery (Forum, Admin, Auth)
- O: Serializery rozszerzalne bez modyfikacji bazowych
- L: Uzytkownik dziedziczy AbstractUser zachowując kontrakt
- I: Osobne serializery dla różnych operacji
- D: Kontrolery zależą od serwisów (abstrakcja)

Clean Code:
- Czytelne nazwy (pobierz_watki_wg_kategorii)
- Małe funkcje (max 30 linii)
- Docstringi wyjaśniające "dlaczego"
- Spójne formatowanie
- Try-catch na każdym API call
- 42 testy
